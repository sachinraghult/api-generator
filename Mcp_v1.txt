Slide Visual: A clean, clear, updated diagram showing the MCP Host, MCP Client, MCP Server, and Data Sources. Speaker Notes: "Let’s look at how this actually works under the hood. The architecture is elegantly simple and consists of four main parts:
The MCP Host: This is the AI application itself, like the Cursor code editor or Claude Desktop

The MCP Client: This lives inside the Host. It initiates the connection and routes requests
.
The MCP Server: This is the lightweight program you build. It safely exposes your data and tools

Data Sources: This is where your data lives, whether it’s a local SQLite database, a file system, or an external API

Slide 5: MCP vs. Traditional APIs
Slide Visual: A side-by-side comparison table. Left side: Traditional APIs (Upstream/Downstream Systems). Right side: MCP (AI Agents). Speaker Notes: "If you are a backend developer, you might be wondering, 'Don't traditional REST APIs already do this?' Not exactly. Traditional APIs are built for upstream or downstream systems and human developers. They require us to manually read documentation, map out explicit endpoints, and handle stateless requests
. MCP is built specifically for AI agents. Instead of explicit endpoints, MCP allows an AI agent to dynamically ask, 'What capabilities do you have?' The MCP server responds with a list of tools the AI can automatically understand and use
. Plus, MCP maintains stateful sessions, allowing the AI to chain multiple operations together logically

Slide 6: The Three Core Primitives
Slide Visual: Icons representing "Resources" (documents), "Prompts" (templates), and "Tools" (gears/functions). Speaker Notes: "So, what exactly does your MCP server give to the AI? It exposes three core primitives:
Resources: Think of these as read-only context. It’s data the AI can read, like file contents, database schemas, or live logs

Prompts: These are reusable templates that help structure interactions, giving the AI specific instructions or few-shot examples

Tools: These are executable functions. This allows the AI to actually do things—like running a database query, pushing code to GitHub, or calling an API

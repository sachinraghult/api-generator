Slide 4: Understanding the MCP Architecture
Slide Visual: Clear diagram showing the MCP Host, MCP Client, MCP Server, and Data Sources. Speaker Notes: "The architecture is elegantly simple:
Host: The AI app itself, like Cursor or Claude Desktop
.
Client: Lives inside the Host, managing a 1-to-1 connection with a server
.
Server: The lightweight program you build to safely expose your tools
.
Data Sources: Your databases, files, or APIs
. For local setups, the client and server communicate instantly via standard input/output (stdio), meaning zero network overhead
."
Slide 5: MCP vs. Traditional APIs
Slide Visual: Comparison table: Traditional APIs (Upstream/Downstream Systems) vs. MCP (AI Agents). Speaker Notes: "REST APIs are built for human developers and upstream/downstream systems, requiring explicit endpoints and stateless requests
. MCP is built specifically for AI agents
. Instead of reading API docs, the AI uses dynamic tool discovery to see what a server can do
. Plus, MCP uses stateful sessions, allowing the AI to remember context across a multi-step workflow
."
Slide 6: The Three Core Primitives
Slide Visual: Icons for Resources (documents), Prompts (templates), and Tools (gears). Speaker Notes: "Your MCP server empowers the AI by exposing three core primitives:
Resources: Read-only context, like file contents or database schemas

Prompts: Reusable templates that structure interactions

Tools: Executable functions that let the AI actively do things—like running a query or fetching live data
